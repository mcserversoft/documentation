Date: 16 October 2026 (Europe/Paris). Completed tests and explicit remaining gaps
are recorded below; this is not a claim that every runbook item passed.

## 1. First launch and creation

Target guides: first server, create/import, Java, server settings.
Evidence status: **observed**, limited to this build and Paper setup.

Starting state: no servers in the isolated installation. Copying only the executable
and selected resource directories initially omitted `resources/mcss_config.json`.
The splash reported `Failed to load config file` / `Could not find file` and offered
Abort, Retry, Ignore. Restoring the supplied configuration allowed the welcome
screen to appear. This was a deliberately incomplete test copy, not evidence that
the distributed package fails first launch. The supplied config had no users, API
key, webhooks, Java override, or enabled web API/panel.

Exact creation sequence:

1. Welcome screen **Create** → **Add Server** → **Create New** → **Paper**.
2. **Select file** opens a native picker filtered to **JAR files (*.jar)**.
3. Select the supplied Paper JAR; the dialog reports one selected file.
4. Set **Name** `Example Paper`; **Folder Name** fills automatically. Set **RAM**
   2048 MB and **Port** 25575. Leave **Accept the Minecraft EULA** unchecked.
5. **Create Server** succeeds without EULA acceptance. The dashboard initially
   reports **Offline**. MCSS copies the JAR as `paper.jar` and creates
   `mcss_server_config.json`, `server.properties`, and `eula.txt` with `eula=false`.

For isolation, while stopped, set `server-ip=127.0.0.1`, view distance and simulation
distance 3 in the test server's properties. No firewall/router rule was changed.

Java and first-start sequence:

1. Left navigation **Settings** opens **Program Settings**. The Java section has
   **Global Java Path override (environment variable)** and **Java Path Picker**.
2. Enter the portable runtime's full `bin\java.exe` path. With the server's local
   override empty, **Start** launches Paper. Its console identifies the expected
   Temurin Java 25 runtime.
3. With `eula=false`, Paper reports `You need to agree to the EULA in order to run
   the server. Go to eula.txt for more info.` MCSS returns to **Offline**.
4. After consulting the [Minecraft EULA](https://www.minecraft.net/en-us/eula),
   set `eula=true` in the disposable server while stopped and choose **Start**.
5. Paper reports `Done (5.663s)! For help, type "help"`; MCSS becomes **Online**.
   A Minecraft client connection has not been tested.

The startup log also contains OSHI/Perflib counter errors and terminal-feature
warnings. Paper nevertheless reaches readiness. No performance-counter repair was
attempted, and these messages must not be presented as a universal MCSS failure.

Server settings: the dashboard cogwheel opens **Edit Server** with **General**,
**Advanced**, **Crash Handling**, and **Update Server**. General includes server
name, description, folder path, icon, RAM, port, **Force 'save-all' on server stop**,
and autostart. Advanced includes **Local Java path override**, **Startup Line**,
**View Preview**, **Use Bat file**, **Reload**, **Validate**, and **Edit File**.
The default startup line is `java -Xms256M -Xmx[RAM]M -jar [SERVERTYPE.NAME].jar`.
A local override was saved. With a deliberately nonexistent global executable,
the original Paper server still reached readiness using the valid local override.
The global setting was restored afterward. This verifies precedence for the
tested Startup Line method, not batch launchers or picker discovery.

Crash Handling displays Nothing, Elevated, Aggressive. The descriptions say
Elevated restarts after non-MCSS input and Aggressive after any input, with a
warning about scheduler/backup conflicts. The initial workflows used **Nothing**;
subsequent policy tests are recorded under operation below.

## 2. Backup and recovery

Target guides: backup/restore and custom filenames.
Evidence status: **observed** for the stopped-server path and recovery below.

The console accepts Minecraft commands without a leading slash. An initial
`setblock 0 100 0 minecraft:diamond_block` failed with `That position is not loaded`.
`scoreboard objectives add mcss_recovery dummy` then succeeded with
`Created new objective [mcss_recovery]`. This is persistent Minecraft world data,
not an MCSS-specific player or world editor.

**Stop** completed Paper's player/world save sequence and MCSS became **Offline**.
The marker file is `world/data/minecraft/scoreboard.dat`, SHA-256 before backup:
`604921804f988d766d3d19ff33f909ff08a4f2f70ea8d7c86872ab513666290c`.
Extra text fixtures were added under the server root, `plugins/example-data/`,
`mods/`, and `excluded-example/`; they are not functional plugins or mods.

**Backups → Create new Backup** opens **Create Backup**. Observed controls:
Name, Compression (initially High compression), Destination, Blacklist,
Delete old backups, Suspend server (initially checked), Backup now.
Suspend server's description says it shuts down the server and starts it after
the backup. Delete-old-backups describes keeping 15, configurable globally.

Test `recovery-check`: server stopped, Suspend server unchecked, Backup now checked,
blacklist empty, deletion unchecked. A relative Destination `backups` was accepted
by the form but produced **BACKUP FAILED** with no archive found in the lab's backup
directory. The same template with an existing absolute destination then succeeded.
The initial relative-path screenshot was removed rather than published as a
working setup. No universal cause for relative-path failures is inferred.

Template menu: Edit, Run Backup, Schedule this Backup, Remove from List.
Failed-history menu: Remove from List. No restore command observed in those menus;
this does not establish absence elsewhere in MCSS.

Successful retry: **Edit → Destination**, existing absolute lab backup directory,
**Save**, template menu **Run Backup**. MCSS displayed **BACKUP DONE** and produced
`recovery-check_1792106275.zip`, 216,831,063 bytes. It contains 370 entries including
directories, 232,300,408 total uncompressed bytes. No custom blacklist was used.
Inspected entries include `paper.jar`, `eula.txt`, `server.properties`,
`mcss_server_config.json`, libraries/logs, `recovery-marker.txt`, plugin/mod text
fixtures, the unexcluded candidate directory, and the scoreboard marker. The
application-wide `resources/mcss_config.json` is not in this server ZIP.

Recovery: extract into a new directory; the scoreboard SHA-256 matches the
pre-backup value. **File → Import Server.. → Paper → Select server to import**,
select extracted `server.properties`. The native picker displays **All files
(*.*)**, not an acceptance whitelist. The form initially uses RAM 1024 MB, port
25565, and name/folder `server`. Set Recovery Paper, 2048 MB, port 25576, then
**Import Server**. The source remains intact; MCSS copies the folder and creates
a new ID/configuration, with no source local Java override or backup templates.
It retains `server-ip=127.0.0.1`, world files and text fixtures. **Start** reaches
Paper readiness (`Done (3.916s)!`). `scoreboard objectives list` returns
`There are 1 objective(s): [mcss_recovery]`. Stop normally afterward.

Successful-history menu: **Show in File Explorer**, **Remove from List**. No
restore command was present in the inspected template/history menus. This test
used filesystem extraction plus MCSS import, not an asserted built-in restore UI.
No client joined; retention deletion, blacklist matching, Suspend server,
consistent live backup, plugin execution, and external database recovery remain
untested.

## 3. Operation and scheduler

Evidence status: **observed**, scoped to Paper and the listed cases.

**Restart** caused a normal save/shutdown sequence, then Paper reached readiness
again (`Done (3.951s)!`). **Kill** is a separate control; forced termination was
not used through that button. Both independent server tabs were operated on
distinct loopback ports.

Elevated test in the relocated lab: choose Elevated in Crash Handling, Save,
Start. Minecraft `stop` typed through the MCSS console stops normally and remains
Offline; this input went through MCSS. An earlier typing attempt opened a settings
dialog instead of reaching the console, produced no server stop, and was discarded
as an automation/focus failure. The input was explicitly refocused and the command
was then visibly entered and submitted.

For the non-MCSS exit test, start again and verify the sole `java.exe` child of
the relocated lab `mcss.exe`, with the expected private portable runtime and
`@launch.args` command line. Terminate **only that verified child process** through
the shell; do not terminate unrelated Java processes. Elevated relaunches Paper,
which reaches readiness at 01:45:47 (`Done (3.873s)!`). This is an intentional
disposable abrupt-exit test, not recommended routine shutdown. Normal MCSS Stop
then saves/exits at 01:46:05; it is still Offline at 01:46:18. This verifies the
distinction for the tested process exit and normal stop, not every crash type.

Aggressive test: while stopped, select Aggressive, Save, Start; readiness at
01:47:06. Choose MCSS **Stop**. The server saves/exits and automatically starts
again, reaching readiness at 01:47:26 (`Done (3.879s)!`). This validates that
intentional-stop case, not scheduler/backup interactions. The lab is then exited
normally and its stopped test configuration returned to Nothing.

Scheduler creation: **Scheduler → Create new Task**. Trigger chooser: Fixed Time
(local 24-hour `hh:mm:ss`), Interval (seconds after start/restart), Timeless (no
scheduling). Repeat and player-count conditions are available. **Next → Jobs
Overview → Add Job** offers Server Action, Run Console Commands, Start Backup,
Run PowerShell Command, Run CMD Command. Server Action dropdown: Stop, Start,
Kill, Restart. Add Delay, enabled state, ordering, edit/removal are exposed.
Shell jobs, multiple-command separators, and delay behavior were not executed.

Test: name Recovery marker check; Interval 10; Repeat cleared; default no player
restriction. Add Run Console Commands job `scoreboard objectives list`, enabled.
Review summary then **Create**. Start Recovery Paper. Paper readiness is logged
at 01:23:18; the objective list is logged at 01:23:28. This validates that interval
case. Fixed Time, Timeless/manual execution, missed tasks, DST/time-zone changes,
player conditions, restart countdown reset, and backup jobs remain untested.
The experimental task was disabled in the stopped installation after the test.

## 4–5. Remote service, authentication, and API evidence

Evidence status: **observed** with important unresolved authorization results.
User explicitly approved the administrator/restricted test scopes after automatic
review required more specific approval for assigning admin rights.

Native UI: Web Panel reports disabled state and links to **Manage Users & API
Keys**. **Remote Access Manager** separates Web Panel Users and API Keys. New-key
form initially selects **All** and **Assign admin rights**. Created Documentation
administrator (admin, all servers) and Documentation restricted (non-admin,
Custom, Example Paper only, only View Stats). In Server Selector, selecting a
server's checkbox enabled all its switches; toggling only View Stats from an empty
selection selected the server with just that permission. Persisted configuration
and API key metadata confirmed those flags.

Program Settings → Remote Access / Developer API has Enable Web API, Hide
introduction page, Enable Web Panel, Show Web API/Panel on startup, Enable SSL,
Panel / API Port Number. No Allow Remote Access control appeared in that group.
The UI says changes apply on leaving the page without restarting MCSS; enabling
the API/panel/SSL and leaving the page did start the service. Show-on-startup also
opened the system browser during setup; no unrelated browser content was saved.

Windows reported port 25560 listening on `::`, owned by the isolated lab's
`mcss.exe` process. No router/public forwarding or firewall rule was created.
Requests were sent only to 127.0.0.1. Game servers remained on separate ports
25575/25576. Do not describe the wildcard management listener as loopback-only.

SSL generated `resources/certificate.pfx`. The inspected public certificate has
subject and issuer CN `MC Server Soft API`, no reported SAN, validity 15 October
2026–15 October 2027. Standard Node trust validation failed with
`UNABLE_TO_VERIFY_LEAF_SIGNATURE`; ordinary browser trust/login was not verified
and no browser interstitial was bypassed. For API-only lab checks, an exact
public-certificate fingerprint was verified before sending HTTP credentials,
after independently checking listener ownership. This is an isolated test trust
mechanism, not recommended production/browser certificate instructions. Reading
the PFX with the empty configured certificate secret failed; no password was
guessed or certificate-import workflow inferred.

Live `GET /api/v2`: MCSS 13.10.0, API 2.4.1, non-dev build. Missing/invalid keys
return 401. Both disposable keys authenticate through the `apiKey` header.
The [official product API link](https://www.mcserversoft.com/apidocs) redirects
to the historical API_2.4.1 documentation, not a fresh installed-build export.
Bundled panel source was inspected for its actual `POST /auth` request format.
`GET /api/v1` returned 404. No v1 security contract was guessed or changed.

## 6. Relocation and argument-file launch

Evidence status: **observed** for same-computer folder relocation; upgrades pending.

Exit MCSS normally with both servers offline; retain the original installation.
Copy the entire lab MCSS directory to `moved-mcss`. Before copying, confirm zero
keys/users, disable API/panel and the test schedule. Hide the automatically
displayed IP in the disposable configuration to prepare safe new captures.
No original supplied installation was changed.

The moved executable loads both server entries. Recovery Paper's scoreboard hash
matches the pre-copy value. Add `launch.args` in that server folder containing
`-Xms256M`, `-Xmx2048M`, `-jar`, `paper.jar`, `--nogui`. In **Edit Server → Advanced**,
set **Startup Line** `java @launch.args`, local Java override empty, Save, Start.
Paper reaches readiness (`Done (3.970s)!`) and `scoreboard objectives list` again
returns `mcss_recovery`. The global portable runtime remains at its previous
absolute path outside the MCSS installation. This validates a representative
argument-file launch with Paper, not a real loader or generated pack launcher.

Same-machine copy/move does not verify fresh Windows prerequisites, a different
host, changed external Java/plugin/database paths, certificate migration, MCSS
upgrades, or a Minecraft world-version upgrade.

## Documentation validation

Node `24.19.0`. Bun `1.3.11` normal and baseline binaries panic during frozen
dependency installation in the sandbox. Bun `1.4.3` reports `EBADF accessing
temporary directory` there, including with workspace temporary/cache directories.
The same frozen install succeeds with Bun `1.4.3` outside the sandbox. No lockfile
change. Final validation used the README's Bun `1.3.11` outside the sandbox:
`bun run build`, `bun run typecheck`, and `bun run check:export` all passed.
The final export check covered 246 HTML pages, 74 API operations, 25 legacy
routes, links/assets/bookmarks, and guide/API search. The build emitted two
nonfatal CSS optimizer warnings about `::highlight`; it completed successfully.

Rendered review covered all 12 changed/new guide routes at a 390-pixel narrow
viewport, plus desktop views of the first-server and scheduling guides. No
horizontal overflow was observed. New guide screenshots link to their full-size
assets; one link was opened to verify the image. Search returned the new
**Schedule server tasks** and **Move an MCSS installation** guides as their
respective first results. The temporary viewport override was reset.

Final lab state: MCSS and its test servers exited; both installations have remote
API/panel disabled and zero temporary users/API keys. Test schedules and automatic
starts are disabled, and the moved Recovery Paper server's Keep Online policy
was restored to Nothing. Raw evidence and disposable installations remain outside
the documentation repository. No commit, push, or deployment was performed.
