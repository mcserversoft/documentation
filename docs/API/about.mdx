## What the API provides [#-api-about]

The MCSS API lets software inspect and manage servers. The supplied reference covers operations such as server actions, console commands, statistics, backups, scheduled tasks, webhooks, and user/key management.

Use the [v2 reference](/apis/v2) for current integrations targeting MCSS 13.10.0. API version numbers and MCSS application version numbers are different: `/api/v2` does not mean MCSS version 2.

## Enable access [#-api-enable]

Open **File → Options** and enable **Web API** in the remote-access/API settings. Enable **Allow Remote Access** only if calls must arrive from another computer.

Check the configured port and whether SSL is enabled. This documentation's examples use port `25560`; your configured value takes precedence. The Minecraft game port, often `25565`, is a different service.

## Create an API key [#-api-keys]

Open **Web Panel → Manage Users & API Keys** and create a key with the required server access and permissions.

![Creating an API key in MCSS](/img/docs/api/remote-access-manager-create-key.png)

Authenticate using the **`apiKey` request header**. Keep its value private and outside source control. If a key is exposed, revoke/delete it and create a replacement; update the applications that used it.

Reserve [admin permission](/API/admin) for integrations that actually need user/key or MCSS-level management.

## Make the first request [#-api-calls]

Start with a read-only call. Set the key in your local environment using your normal secret-handling method; do not put a real key in a shared example.

This PowerShell example assumes `MCSS_API_KEY` is already set. Replace the base URI with the configured address, scheme, and port:

```powershell
$baseUri = 'https://your-mcss-host:25560'
$headers = @{ apiKey = $env:MCSS_API_KEY }
Invoke-RestMethod -Method Get -Uri "$baseUri/api/v2" -Headers $headers
```

The [version endpoint](/apis/v2/general/get-api-version) documents the response fields. Inspect the response from your instance rather than treating the old sample version values as current.

A second read-only call lists the servers visible to the integration:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUri/api/v2/servers" -Headers $headers
```

For HTTPS errors, fix the address/certificate trust configuration. Do not make disabling certificate verification part of a normal integration.

### HTTP clients [#-standalone-software]

An HTTP client such as [Postman](https://www.postman.com/downloads/) or [Insomnia](https://insomnia.rest/download) can send the same method, URI, and `apiKey` header. Use a local/private environment for credentials and check what the tool syncs before storing a production key.

### Editor tools and scripts [#-ide-extensions]

You can also use an editor's HTTP client, PowerShell, or a standard HTTP library. The important pieces are identical: the configured base URI, correct API version, method, headers, and any body documented by the endpoint.

## Find endpoints and diagnose failures [#-api-endpoints]

Use [API versions](/API/endpoints), then open the generated endpoint page for its schema and examples.

For authentication failures, check that the `apiKey` header is present and the key is still valid. For access failures, check both server assignment and permissions. Inspect the endpoint's documented status codes and the actual response body rather than assuming every failure is a networking problem.

Browser-based API playgrounds call your instance from the browser. Reachability, certificate trust, mixed-content rules, and cross-origin policy can prevent a request that otherwise works from a local script. The documentation site does not proxy requests to your instance.
