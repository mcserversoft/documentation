title: "MCSS and Windows issues"
description: "Handle application crashes, native dependencies, process recovery, and older Windows workarounds."
---

This page concerns the MCSS application or its Windows environment. If Minecraft starts and exits with a Java/mod error, use [Startup errors](/troubleshooting/startup) instead.

## MCSS closed but the game is still running

Check whether players can still reach the game. If you can join as an operator, use its normal stop command, such as `/stop` for a Java world server, and wait for it to finish saving.

Identify the relevant process in Task Manager if normal shutdown is impossible. MCSS's documented **Quick Options → Kill all Java processes** action affects **every Java process**, including unrelated applications and clients. Reserve forced termination for a deliberate last resort; unsaved work can be lost.

Do not start another copy against the same world while the original process still owns it. Back up after recovery and check the logs before reopening access.

## Missing Scintilla or Visual C++ runtime

The older documentation includes a crash involving `Scintilla.dll` when opening a console/player editor. A missing native dependency or incompatible architecture can be relevant; the filename alone does not establish the cause.

Use the prerequisites supplied with your MCSS release and Microsoft's [supported Visual C++ Redistributable downloads](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist). The redistributable architecture must match the application/component that needs it, not simply the operating system's architecture. Do not download individual DLLs from third-party DLL sites.

If installation/repair does not resolve the issue, preserve the exact exception and MCSS logs for support.

## Process-name or performance-counter prompts on older installations

Previous guides covered a process-name registry change introduced in MCSS 11.5 and rebuilding Windows performance counters. Those are historical remedies for specific errors, not prerequisites or optimization steps for every 13.10.0 installation.

Record the exact dialog and Windows version. Use current MCSS support guidance before changing registry or system counter settings. Do not run an administrator repair command merely because a graph displays zero.

## Character encoding problems

Identify where text is corrupted: the game log file, MCSS console, script input, or a particular plugin. Check the file's encoding and reproduce with the relevant Java executable.

Modern Java changed its default charset to UTF-8 starting with JDK 18; this does not mean every Windows console or application stream uses that charset. See [OpenJDK's explanation of JEP 400](https://inside.java/2021/12/10/quality-heads-up/).

A JVM property belongs before the game launch target if a server's own instructions call for one. Do not change Windows' system-wide locale or apply `-Dfile.encoding=UTF-8` to every server as an untested universal fix. Include a minimal example and the actual Java version in a [support report](/troubleshooting/logs-and-support).
