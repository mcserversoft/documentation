---
title: "Move an MCSS installation"
description: "Copy a stopped installation, retain its configuration, and review paths before starting the new copy."
---

Moving MCSS, upgrading MCSS, and importing a Minecraft server are separate operations. An [MCSS server import](/basic/import-server/supported-server-files) creates a new server configuration; it is not a substitute for preserving the application installation.

## Prepare and copy

1. Record the MCSS, server software, and Java versions. Make a [recoverable backup](/backups/backup-and-restore).
2. Disable scheduled tasks and automatic starts/restarts that could interfere with the move.
3. Stop each server normally. Use **File → Exit** to close MCSS completely; closing the window can instead minimize it, depending on Program Settings.
4. Copy the complete MCSS installation to the new location. Retain the original and the backup until verification is complete.

Keep `resources`, server directories, and application/per-server configuration together. A tested server backup included `mcss_server_config.json` but did not include the application-wide `resources/mcss_config.json`; a server ZIP alone does not preserve the whole installation.

## Review paths and start one copy

Check global and local Java overrides, batch/argument files, backup destinations, and any plugin/mod paths outside the installation. Absolute paths can still refer to the old location or to software that is absent on another computer. Review remote-management settings and credentials before starting a copied instance.

Start the copied `mcss.exe`, confirm the expected servers appear, and start just the test instance. Read the console for readiness and verify the expected world data. Keep the original copy stopped so the two copies cannot compete for the same ports or external data.

## Scope of the relocation test

On 16 October 2026, the stopped **MCSS 13.10.0** test installation was copied to a different folder on the **same Windows computer**. Both servers were recognized. Recovery Paper started with `java @launch.args`, reached readiness, and returned its saved scoreboard objective. The world marker file had the same hash before and after copying.

The portable Java runtime remained at its existing absolute path outside the MCSS folder. Remote services and experimental schedules were disabled, and temporary credentials had been revoked before copying. This verifies that specific same-computer folder relocation; moving to a new computer, native-runtime prerequisites, certificate migration, external databases, and application upgrades require separate tests.
