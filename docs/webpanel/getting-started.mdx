title: "Use the remote web panel"
description: "Enable the panel, test locally, then decide how to allow administration from other devices."
---

The MCSS web panel is a **management interface**. Its address and permissions are separate from the Minecraft game server. You do not need to expose it to let players join.

## Enable the panel [#-enable-panel]

Open **File → Options → Remote Access / Developer API**.

1. Enable the [Web API](/API/about#-api-enable) if it is not already enabled.
2. Enable **Web Panel**.
3. Leave **Program Settings** to apply the changes. MCSS 13.10.0 displays **The webserver will apply these changes after leaving this page. No need to restart mcss.** This was exercised in the Windows test.
4. Create the appropriate [panel user](/webpanel/users).

## Test on the host computer [#-local-access]

Use the configured scheme and port. The examples use port **25560**; use your actual configuration if it differs.

```text
http://localhost:25560
```

If SSL/HTTPS is enabled, use `https://` instead. `localhost` refers only to the computer where the browser is running. The **Show Web API/Panel on startup** option can open the panel automatically.

## Access from the LAN [#-LAN-access]

No **Allow Remote Access** control appeared in the inspected MCSS 13.10.0 Remote Access settings. In the test, Windows reported the management listener on IPv6 wildcard `::`, rather than loopback only. Do not assume that using `localhost` in your browser restricts the service's binding. Review the host's firewall and the intended administration route before enabling access from another device.

From the other device, use the MCSS computer's [LAN address](/networking/find-ip) and the panel port. Test with a restricted user account and verify which servers it can access.

## Access from outside your network [#-anywhere-access]

Choose an administration route deliberately. A private VPN can limit access to authorized devices; a public route needs suitable authentication, access restrictions, and HTTPS.

If you choose direct IPv4 access, the panel needs its own forwarding rule, separate from the game port. Forward only the configured management port and verify it from outside. A TCP game tunnel does not by itself add encryption or access control to the panel.

The MCSS settings include **Enable SSL**. Use `https://` when it is enabled. For certificate and reverse-proxy configuration, follow the instructions for the components you actually deploy rather than assuming MCSS exposes a particular certificate-import setting.

## When a browser reports a certificate problem

A warning can mean an untrusted issuer, a name/address mismatch, or an expired certificate. Check the destination and certificate before entering credentials. Do not treat every warning as a routine prompt to bypass.

Encryption and trust are different checks: HTTPS can encrypt a connection while the browser is unable to verify who operates the endpoint. See [MDN's TLS overview](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Transport_Layer_Security).

If the panel works on the host but not remotely, check the configured service, binding, firewall, and route in that order. Never diagnose it by opening unrelated ports.

The 16 October 2026 test enabled the API/panel with SSL and authenticated disposable panel accounts through the panel's `/auth` endpoint. A restricted session received 403 for an unassigned server and user administration. Browser login, LAN access, and browser-origin enforcement were not verified. The generated certificate did not pass the test client's standard trust validation; no browser warning was bypassed. API-key authorization discrepancies are recorded separately in [API setup](/API/about).
