---
title: "Players cannot connect"
description: "Follow a step-by-step checklist from localhost to the internet to find and fix connection problems."
---

When players cannot join your server, the fastest way to find the problem is to test in order: **first on the server PC**, **then on your home network (LAN)**, and **finally from the internet**. If a server cannot be reached on the computer running it, changing router settings will not help until the local issue is fixed.

## 1. Confirm the game is ready

Before testing connections, check the MCSS console to make sure the server has finished starting up:

- **Wait for `Done`:** Large modpacks and first-time world generation can take a minute or two before the server starts listening for players. If the server stops or restarts immediately, see [Fix startup errors](/troubleshooting/startup).
- **Check the port:** Confirm the `server-port` in your `server.properties` (default `25565` for Java Edition). Make sure players are using the **game port**, not the MCSS Web Panel/API port (`25560`).
- **Match the Minecraft version and modpack:** Ensure the player is launching the exact same Minecraft version, mod loader, and modpack version as the server.

## 2. Test from the server computer

Open Minecraft on the same PC running MCSS and connect using **Direct Connection** to:

```text
localhost:25565
```

*(Replace `25565` if you changed your server port.)*

| What happens | How to fix it |
| --- | --- |
| **You join the server** | Your server is running properly! Move on to [Step 3: Test from a second LAN device](#3-test-from-a-second-lan-device). |
| **Connection refused** | The server isn't listening on that port yet. Check the MCSS console to verify the server is online and check `server-port` in `server.properties`. |
| **Outdated client / Outdated server / Mod mismatch** | Your network connection works! You just need to launch the matching Minecraft version or modpack on your client. |
| **Failed to verify username / Not authenticated** | If you run a proxy (Velocity/BungeeCord) or switched account sessions, restart your Minecraft Launcher and game client so your login token refreshes. |

## 3. Test from a second LAN device

If `localhost` works, test from another computer on the same home network using your server PC's [LAN IPv4 address](/networking/find-ip#find-your-lan-address-on-windows) (for example, `192.168.1.50:25565`).

If `localhost` works on the server PC, but another device at home gets **Connection timed out**, check these common causes:

1. **Windows Firewall on the server PC:** This is the #1 reason LAN connections fail. Follow [Allow game traffic through Windows Firewall](/networking/windows-firewall#choose-the-rule-scope) to allow your server's port or Java executable.
2. **Leave `server-ip=` blank:** Open `server.properties` and make sure `server-ip=` is completely empty. Putting a wrong IP (or your public IP) there prevents the server from accepting connections properly.
3. **Wi-Fi Guest Network or VPN:** Make sure neither computer is connected to a "Guest" Wi-Fi network (which isolates devices from each other) or an active VPN that redirects local traffic.

### Test TCP reachability

On a second Windows PC on your home network, you can test whether the port is reachable before even opening Minecraft by running this command in PowerShell (replace the IP and port with yours):

```powershell
Test-NetConnection -ComputerName 192.168.1.50 -Port 25565
```

- If **`TcpTestSucceeded : True`**, the network path and firewall between the two computers are open.
- If **`TcpTestSucceeded : False`**, Windows Firewall (or a third-party antivirus firewall) on the server PC is most likely blocking the port.

*(Note: `Test-NetConnection` tests TCP ports used by Java Edition; it does not test UDP ports used by Bedrock Edition or Geyser.)*

## 4. Test from outside your network

Once local or LAN connections work, ask a friend outside your home network to connect using your [public IPv4 address](/networking/find-ip#find-your-public-ipv4-address) (or your [playit.gg tunnel address](/advanced/using-playit.gg-with-mcss)).

If LAN works at home, but friends over the internet cannot connect, check the following:

- **Port forwarding rule:** Double-check your [router's port forwarding rule](/networking/port-forwarding#-step-4). Ensure it forwards the right port (`25565`), the right protocol (`TCP` for Java, `UDP` for Bedrock/Geyser), and points to your server PC's current LAN IPv4 address.
- **Your server PC's LAN IP changed:** Run `ipconfig` on the server PC to verify its IPv4 address still matches the address in your router's port forwarding rule.
- **CGNAT or Double NAT:** Check Step 1 of the [port forwarding guide](/networking/port-forwarding#-step-1) to verify your router has a real public IPv4 address. If your ISP uses CGNAT, use [playit.gg](/advanced/using-playit.gg-with-mcss) instead.
- **Using a tunnel (playit.gg):** Make sure the playit.gg agent is running on your server PC and that its local port matches your server's `server-port`. See the [playit.gg troubleshooting steps](/advanced/using-playit.gg-with-mcss#-step-3).

> [!TIP]
> **Friends can join, but you can't join using your public IP?**
> That is normal on many home routers! Most routers do not loop connections to your own public IP back inside your home network (**NAT Loopback**). Keep giving your public IP to friends outside your home, and connect using `localhost` (on the server PC) or your LAN IP (`192.168.x.x` on other home devices) yourself.

## 5. If it fails intermittently

If players can join at first, but suddenly stop being able to connect later on (or the next day):

- **Your PC went to sleep:** Check **Windows Settings → System → Power & sleep** and set **Sleep** to **Never** while plugged in.
- **Your LAN IP or Public IP changed:** Reserve your server PC's LAN IP in your router's DHCP settings so your port forward doesn't break after a reboot. If your ISP occasionally changes your public IPv4 address, check your current public IP on [What Is My IP Address](https://whatismyipaddress.com/) or set up a Dynamic DNS (DDNS) hostname.

Still stuck? Check [Logs and support](/troubleshooting/logs-and-support) and let us know which of the steps above (`localhost`, LAN, or internet) failed and what message appeared on the player's screen.
